# AI Personal Assistant

The current phase provides a text-based FastAPI endpoint backed by Ollama, with a bounded tool loop for read-only workspace access and launching a small allowlist of applications. It does not provide browser automation, terminal execution, file writes/deletes, persistent conversation history, or memory.

## Requirements

- Python 3.10 or newer
- Ollama installed and running locally (or an Ollama-compatible server)
- A model pulled into Ollama, for example `ollama pull llama3.2`

## Setup

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:OLLAMA_BASE_URL = "http://localhost:11434"
$env:OLLAMA_MODEL = "llama3.2"
$env:ASSISTANT_WORKSPACE_ROOT = (Get-Location).Path
```

The same settings can be exported in the shell or service environment. `.env.example` documents them; the application does not load `.env` files automatically.

## Run

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Send a text request:

```powershell
Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8000/api/assistant/message `
  -ContentType "application/json" `
  -Body '{"message":"Explain what FastAPI is in one sentence."}'
```

The response is generated by the configured Ollama model. If Ollama is unavailable, the endpoint returns HTTP 503 with a clear error instead of a success placeholder. Available tools can only read UTF-8 files and list entries under `ASSISTANT_WORKSPACE_ROOT`, or launch `chrome`, `edge`, `notepad`, and `calculator` when discoverable on Windows. File reads are limited to 1 MB and directory listings to 200 entries. No arbitrary shell commands are accepted.

## Test

```powershell
python -m pytest
```

Tests verify request construction, returned model content, explicit handling of an Ollama connection failure, the real tool-call round trip, and workspace path boundaries. They use an in-memory HTTP transport and temporary files; they do not contact an external service or launch applications.
